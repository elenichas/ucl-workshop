# Starting points

Five ways to start a project without typing "build me a…". Each one ends in a `PLAN.md` that you read, edit and approve **before** any code is written. Pick the one that matches how you think.

| # | File | Approach | Suits |
|---|---|---|---|
| 1 | [`1-interview-me.md`](1-interview-me.md) | Claude interviews you, one question at a time | Anyone unsure where to begin |
| 2 | [`2-digital-product.md`](2-digital-product.md) | Map users, features, inputs/outputs; must/should/could | Technical, structured thinkers |
| 3 | [`3-editorial-experience.md`](3-editorial-experience.md) | Start from mood, references, typography | Design- and experience-led people |
| 4 | [`4-constraints-first.md`](4-constraints-first.md) | Start from printers, materials, limits | Fabrication-minded people |
| 5 | [`5-write-it-yourself.md`](5-write-it-yourself.md) | You write the plan; Claude critiques it | People who want full control |

**Tip:** use Claude Code's **plan mode** for all of these — it can't edit files until you approve.

**After the plan is approved**, always build narrowly:

```text
PLAN.md is approved. Implement step 1 only. When it works, stop,
explain what you did in plain language, and wait for me.
```
